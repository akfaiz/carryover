---
name: e2e-android
description: End-to-end save sync test between the Windows/Linux/macOS CLI and the Android app on an emulator, through a local WebDAV server (PC push, Android pull, Android push, PC pull, conflicts both ways, backups, library merge). Use to verify changes to syncer, cloud, core, library, mobile or the Android sync UI.
---

A PC (`carryover` CLI with an isolated `CARRYOVER_HOME`) and the Android app on an emulator share one WebDAV "cloud": `webdav/main.go` next to this file (`golang.org/x/net/webdav`, no auth, logs each request). The PC reaches it at `http://127.0.0.1:8765`, the emulator at `http://10.0.2.2:8765` (the host's loopback). Plain HTTP works: rclone runs in Go, so Android's cleartext policy doesn't apply. `$T` = a folder in the session scratchpad. Write every file with the Write tool. In Git Bash, `export MSYS_NO_PATHCONV=1` before any `adb` command, or `/sdcard/...` gets rewritten to a Windows path. Drive the app with the mobile-mcp tools (device id from `mobile_list_available_devices`, e.g. `Pixel_8`, not adb's `emulator-5554`); read screens with `mobile_list_elements_on_screen`.

1. **Emulator.** If `adb devices` lists none, start one in the background: `$ANDROID_HOME/emulator/emulator -avd <avd> -no-snapshot-save -no-boot-anim` (`emulator -list-avds`; on this machine `Pixel_8`, x86_64), then wait for `adb shell getprop sys.boot_completed` = 1.
2. **Build, in parallel with the boot.**
   - APK for the emulator's ABI (`adb shell getprop ro.product.cpu.abi`; x86_64 needs `android/amd64`): Windows `.\scripts\android-build.ps1 -Targets 'android/amd64'`, else `scripts/android-build.sh` with the matching target (a full bind, so Go changes are in). Output: `dist/carryover-<version>-android-x86_64-debug.apk`.
   - PC: `go build -o dist/carryover.exe .`
   - Server: copy `webdav/{main.go,go.mod,go.sum}` to `$T/webdav`, `go build -o $T/webdav.exe .` there, and run it in the background: `$T/webdav.exe -dir $T/cloud -addr 127.0.0.1:8765 > $T/webdav.log`. Its "cannot find the path" lines are rclone's existence checks, not failures.
3. **PC setup** (`$T/pc`, saves in `$T/pcsaves`): `rclone.conf` = `[cloud]` / `type = webdav` / `url = http://127.0.0.1:8765` / `vendor = other`; `settings.json` = `{"deviceId":"pc-0000-0000","deviceName":"pc","remote":"cloud","remoteRoot":"Carryover","backupRetention":5,"syncLibrary":true}`; `library.json` with game `game-a` exactly as in the `e2e-sync` skill (native profile, exe appending `pc-session` to `save.txt`). Run `CARRYOVER_HOME=$T/pc dist/carryover.exe run game-a --emulator native --headless` → exit 0, `$T/cloud/Carryover/{library.json,games/game-a/manifest.json,games/game-a/current/saves/save.txt}`.
4. **Android setup.**
   - `adb install -r <apk>`. If the app was installed before, look at `adb shell run-as com.akfaiz.carryover ls -laR files/carryover` first; clear it (`adb shell pm clear com.akfaiz.carryover`) only if it holds nothing worth keeping, otherwise ask.
   - `adb shell appops set com.akfaiz.carryover MANAGE_EXTERNAL_STORAGE allow`, `adb shell pm grant com.akfaiz.carryover android.permission.POST_NOTIFICATIONS`, `adb shell mkdir -p /sdcard/CarryoverTest/saves`.
   - Launch the app once (it writes `files/carryover/settings.json` with the device id derived from `ANDROID_ID`), then `adb shell am force-stop com.akfaiz.carryover`.
   - Write locally and push with `adb exec-in run-as com.akfaiz.carryover sh -c "cat > files/carryover/<file>" < <local file>`: `rclone.conf` as the PC's but `url = http://10.0.2.2:8765`; `settings.json` = the app's own with `"deviceName":"android","remote":"cloud","remoteRoot":"Carryover","backupRetention":5` (keep its `deviceId`).
5. **Library to Android.** Launch, tap "Sync all" → the WebDAV log shows `GET` and `PUT /Carryover/library.json`. The library still shows no games: Android lists only games set up on this device or through an emulator set up here (`GameView.forAndroid`), which is expected. Force-stop, pull `files/carryover/library.json` (`adb exec-out run-as ... cat`), add under `game-a`'s `devices` an entry for the app's device id: `{"deviceName":"android","paths":{"saves":"/sdcard/CarryoverTest/saves"},"launchMode":"direct","updatedAt":"<now, RFC 3339>"}`, push it back, launch → Game A is listed, "Not synced".
6. **Checks**, in order (game page → "Sync now"; the game page's sync does not sync the library, only "Sync all" on the library page does):
   - Android sync → "Synced"; `adb shell cat /sdcard/CarryoverTest/saves/save.txt` = `pc-session`.
   - `adb shell "echo android-session >> /sdcard/CarryoverTest/saves/save.txt"`, Android sync → the cloud's `save.txt` ends with `android-session` and its `manifest.json` says `"deviceName": "android"`; PC `sync game-a --emulator native` → exit 0, `pull`, PC file equals the cloud's.
   - Conflict on Android: append to both sides, PC `sync` first (push), then Android sync → dialog "Game A: saves changed on both sides" with this device's and the cloud's size and device name. "Keep the cloud saves" → Android's file equals the PC's, and `games/game-a/backups/<time>_android_local.zip` holds Android's replaced `saves/save.txt` (read it with Python's `zipfile`, run with `-I`).
   - Conflict on the PC: append to both sides, Android sync first, then PC `sync game-a --emulator native` → exit 3, "planned conflict", nothing changed.
   - Library merge: Android "Sync all", then PC `sync --all` → the PC's `library.json` has Android's device entry for game-a (with the `/sdcard` path) and both devices under `devices` (exit 3 here only reflects the unresolved conflict).
7. **Report** pass/fail per check with the actual output (exit codes, file contents, the dialog's text, WebDAV log lines). **Clean up**: stop the WebDAV server, `adb shell rm -rf /sdcard/CarryoverTest`, `adb shell pm clear com.akfaiz.carryover` (the app still points at the dead server otherwise), remove `$T`. Leave the emulator running unless asked to shut it down.

Not covered: folders granted through the system picker (`:saf:` paths; set one through Edit game → the save folder → the picker to test `localfs`/the `saf` backend), playing an Android game (detached sessions), and setting up the WebDAV remote through the app's Cloud page.
